# 认识本人身边的人：每人一份「对TA的理解」

本人每天和同事、客户打交道。心响替本人做事时，要知道找来的人是谁、在意什么、喜欢什么样的东西。这一轮给几个人各写一份理解，写进心响的通讯录；以后做和TA有关的事，这份理解会放进简报里。

## 要交出什么

当前文件夹的 `people.json`：

```json
[{"name": "张三", "text": "## 是谁\n…\n\n## 在意什么\n…\n\n## 怎么跟TA打交道\n…\n\n## 最近和本人在做的事\n…"}]
```

- `name` 照 `people/` 里的文件名（不带 `.md`），一个字都不改。
- `text` 是 Markdown，用下面四节，材料里看不出来的节就不写（至少写「是谁」和另外一节）：
  - `## 是谁`：岗位或角色、负责哪块、和本人是什么关系（同事、上级、下属、客户、合作方）。
  - `## 在意什么`：TA 反复提的目标、标准、顾虑，TA 拍板时看重什么。
  - `## 怎么跟TA打交道`：TA 习惯怎么沟通（发文档还是口头、要结论还是要过程），给 TA 的东西要注意什么。
  - `## 最近和本人在做的事`：正在一起推进的事、TA 在等本人的、本人在等 TA 的。写清是哪天的。
- 每节 2~5 条，每条一句完整的话，后面括号写依据，比如「（11-25 需求对齐会）」「（11-24 私聊）」。总共不超过 600 字。

## 输入

- `people/<名字>.md`：一人一份材料，程序已从本地记录里找好：
  - 本人写的（有的话）：以这里为准，不要改它的意思；
  - 上一次写的理解（有的话）：有新材料就更新，没被推翻的保留；
  - 和 TA 有关的事项、TA 在会上说的、TA 在聊天里说的（私聊里本人的话也在，标着「我」）。

## 怎么写

1. **只写材料里看得到的。** 猜的岗位、性格评价、没出现过的偏好一律不写。宁可少写一节，也不要编。
2. **写对做事有用的。** 比如「要结论先行，不看长篇过程」「关心上线时间，常问排期」，而不是「TA 很认真」。
3. **说话人要分清。** 私聊里标着「我」的是本人说的，不是 TA 说的；会上只写 TA 自己说的话。
4. **不写隐私和情绪评价。** 不写身体状况、家庭、薪资、对 TA 个人的好恶。
5. 材料太少、写不出两节的人，就不放进 `people.json`。一个人都写不出来就交 `[]`。

## 交了之后

程序核对格式后存进通讯录。本人在「事项 → 按人」里能看到，能补充自己的话，也能点「重新理解」让你再写一次。
