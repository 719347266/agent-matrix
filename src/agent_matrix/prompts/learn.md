# 学经验：从本人的评审和反馈里，找出以后做别的事也用得上的做法

## 要交出什么

当前文件夹的 `learned.json`：`{"drafts": [...]}`，给经验库的草稿，一轮最多 3 份。没有值得学的就写 `{"drafts": []}`，这是正常结果。写入失败就在最终回复里原样返回同样的完整 JSON，心响会读取。

草稿不会直接生效：本人在「记忆 → 记忆更新」里点「用」才写进经验库。

## 输入

- `outcomes.json`：本人最近对交付的评审：`通过` / `退回` / `要改`，带原因、是哪件事、哪个项目、哪类交付（方案、周报、数据汇总……），以及 `memory`：做这份交付的 AI 说自己读了并照着做了哪几份经验（`null` = 老交付，没记）。
- `feedback.json`：本人最近对 AI 说过的话：退回意见、补充要求、对话里的纠正。
- `记忆/`：现在的经验库，一份一个文件；`记忆/目录.md` 是目录（`名字 — 什么时候打开`）。

## 什么算经验

- **能用在很多件事上**：「给老板的汇报只留结论和数据，不写过程」「查线上数据先核 dev/test 表结构，给可直接跑的 SQL」。
- 同类交付连续被通过，说明当时的做法是对的，也可以总结成经验，写清从哪几件看出来的。

## 什么时候不提（提了会被扔掉）

经验库只存经验，不存事实。经验是「下次做同类动作时怎么判断、怎么做」，过一两个月还成立；事实会过期，要用时去现场查（Jira、Slack、代码、git、文档）。下面这些都不提：

- **事实**：谁在跟哪张单、某张单转发过没有、某个分支/提交/配置现在是什么、某个仓库在哪。
- **只对这一件事成立**的结论或要求（「这单本人自己改」「预算改成 600」），留在那件事里。
- **调试过程和绕路办法**：这次怎么绕过沙箱、权限、某个报错。环境问题该修环境；真值得留的只有「下次怎么才不会掉进去」的一句判断，不是一串步骤。
- **没依据的**：拿不出本人原话或具体哪几件事，就不提。
- **为了有产出而提**。一轮下来没什么值得记，是最常见的情况，交空的就行。

本人一句话里既有事实又有规矩时，只记规矩。人名、单号、日期只写进 `why` 给本人审，不写进正文：

- ✗ 正文「#36（LGS-84）经办人是莫慧文，11-25 已转发给 Cara，所以先看经办人」
- ✓ 正文「接没人领的单子前，先看经办人和来源群里有没有人在跟，有人跟就不重做」；`why` 写「#36 LGS-84：莫慧文已在跟」

正文的 `**Why:**` 写道理（为什么这样做才对），不写哪天哪单发生了什么。

## 先看库里有没有

1. 同一个意思库里已经有了：不要再加。
2. 库里有，但本人的新反馈说明它错了或过时了：`revise` 改掉那一段，或 `remove` 删掉。不要在旁边再加一段对的：两段会同时被读到，比没有经验还糟。
3. 读了某份经验照着做却被退回（看 `outcomes.json` 的 `memory`）：先看退回原因是不是这份经验造成的。是才改它；退回的是别的毛病就不动。
4. 交付该用某份经验却没用（`memory` 里没有它，退回原因正是它讲的事）：多半是它的目录描述没写到这个动作，用 `describe` 改描述。
5. 新经验：优先 `append` 到最贴近的那一份；没有合适的才 `create`。

## 草稿格式

```json
{"drafts": [
  {"mode": "append", "name": "查线上数据经验", "body": "## 统计商家数时排除开发店\n统计商家数量时，排除 Shopify Development 套餐的店铺。\n**Why:** 开发店不是真商家，算进去数字会虚高。\n**How to apply:** 任何按商家计数的 SQL 都加上套餐过滤，交付里写明排除了多少家。",
   "why": "#27 要改：要排除一下 Development 套餐的"},
  {"mode": "create", "name": "发 PR 经验", "description": "要建分支、提交代码、发 PR、通知 reviewer 时打开。里面是从哪切分支、PR 发到哪、通知怎么发。",
   "body": "## 用 cw5-pr-notify 发 PR 并通知群\n……\n**Why:** ……\n**How to apply:** ……", "why": "#12、#15 两次要改：用 cw5-pr-notify 把 PR 的通知发到 dev 群"},
  {"mode": "revise", "name": "做事通用规矩", "old_text": "（逐字抄要改的那一段）", "body": "（改好后的那一段）", "why": "11-20 本人说……"},
  {"mode": "remove", "name": "做事通用规矩", "old_text": "（逐字抄要删的那一段）", "why": "被 11-21 的评审推翻：……"},
  {"mode": "describe", "name": "查线上数据经验", "description": "要查线上数据、写 SQL、统计商家或订单时打开。", "why": "#30 写 SQL 时没想到读它"}
]}
```

- 每一节：`## 主题` 一句能照做的话；下面写做法；`**Why:**` 为什么这样做才对（道理，不写单号日期）；`**How to apply:**` 什么情况下用、怎么用。
- `description`：**做哪些动作时打开**，用动词写动作，不写话题（「要写 SQL、统计商家时打开」，不是「商家统计相关」）。120 字内。AI 是拿自己要做的动作来比这句话的，写成话题就召回不到。
- `old_text` 要从文件里逐字抄，多抄几行让它只对上一处。
- 每份都要 `why`：从哪几件事、本人哪句话学来的，原样引用一小段。
