# 学规矩：从本人的评审和反馈里，找出以后做别的事也用得上的做法

## 要交出什么

当前文件夹的 `learned.json`：新学到的规矩，以及已有规矩这一轮的战绩。写入失败就在最终回复里原样返回同样的完整 JSON，心响会读取。

## 输入

- `outcomes.json`：本人最近对交付的评审：`通过` / `退回` / `要改`，带原因、是哪件事、哪个项目（project_id）、哪类交付（方案、周报、数据汇总……）。
- `feedback.json`：本人最近对 AI 说过的话：退回意见、补充要求、对话里的纠正。
- `rules.json`：已有的规矩，每条带编号、适用范围（scope）、来源和战绩（wins 通过次数 / losses 退回次数）。

## 什么算规矩

- **能用在很多件事上**：「给老板的汇报只留结论和数据，不写过程」「对外文案先给两版让我挑」「给客户的方案不写内部代号」。
- 「客户、用户想要什么、不想要什么」也算，范围写到对应项目。
- **只针对这一件事的要求不算**（「预算改成 600」「加上竞品 A」），那留在那件事里。
- 同类交付连续被通过，说明当时的做法是对的，也可以总结成规矩，写清从哪几件看出来的。
- 已有规矩里有意思一样的，不要重复加，改成给它记一次战绩。

## 输出格式

```json
{"add": [{"rule": "给老板的汇报只留结论和关键数据，不写过程", "why": "#12、#15 退回：只保留投流策略和ROI", "scope": "type:周报"}],
 "wins": [3], "losses": [], "retire": []}
```

- `add`：一轮最多 3 条，没有值得学的就留空。`rule` 40 字以内，一句能直接照做的话；`why` 写清从哪几件事、本人哪句话学来的，原样引用一小段。
- `scope`：`""` 所有事都适用；`"project:<项目编号>"` 只在这个项目里（看不出项目就用 `""`）；`"type:<交付类型>"` 只在做这类交付时，比如 `"type:方案"`。
- `wins`：本轮评审里被照着做并通过的已有规矩编号。
- `losses`：被照着做却被退回、或者和本人的话冲突的已有规矩编号。
- `retire`：只能填来源是「AI 学的」、并且已被本人新反馈推翻的规矩编号。
