# 从本人的评审和反馈里学规矩

- `outcomes.json`：本人最近对交付的评审：`通过` / `退回` / `要改`，带原因、是哪件事、哪个项目、哪类交付（方案/周报/数据汇总…）。
- `feedback.json`：本人最近对 AI 说过的话：退回意见、补充要求、在对话里的纠正。
- `rules.json`：现在已有的规矩，每条带编号、适用范围（scope）和战绩（wins 通过次数 / losses 退回次数）。

目标：找出**以后做别的事也用得上**的规矩，并且给已有规矩记战绩。写进 `learned.json` 就结束。

## 什么算规矩

- 能用在很多件事上：比如「老板汇报只留结论和数据，不写过程」「对外文案先给两版让我挑」「给客户的方案不写内部代号」。
- 「客户/用户想要什么、不想要什么」也是规矩，范围写到对应项目。
- 只针对这一件事的具体要求不算（「预算改成 600」「加上竞品 A」），留在那件事里。
- 已有规矩里有意思一样的，不要重复加，改成给它记一次战绩。
- 被通过的交付也有信息：同类交付连续被通过，说明当时的做法是对的，可以总结成规矩（写清从哪几件看出来的）。

## 范围（scope）

- `""`：所有事都适用。
- `"project:<项目编号>"`：只在这个项目里适用（编号见 outcomes 里的 project_id；看不出项目就用全部）。
- `"type:<交付类型>"`：只在做这类交付时适用，比如 `"type:方案"`、`"type:周报"`。

## 写法

- 每条 40 字以内，写成一句能直接照做的话。
- `why` 写清从哪几件事、本人哪句话学来的，原样引用一小段。
- 一轮最多新增 3 条；没有值得学的，`add` 留空，这是正常结果。
- `wins`：本轮评审里，哪些已有规矩被**照着做并通过**了（填规矩编号）。
- `losses`：哪些已有规矩被照着做却被退回，或者本人的话和它冲突（填规矩编号）。
- `retire`：只能填来源是「AI 学的」、并且已经被本人的新反馈推翻的规矩编号。

## 输出格式（learned.json）

```json
{"add": [{"rule": "给老板的汇报只留结论和关键数据，不写过程", "why": "#12、#15 退回：只保留投流策略和ROI", "scope": "type:周报"}],
 "wins": [3], "losses": [], "retire": []}
```

只写 `learned.json`，不改任何东西。
