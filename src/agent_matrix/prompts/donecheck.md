# 看本人的事办完没有：找到办完的证据才算

本人手上这几件事还开着，可能早就办完了，只是没人回来点「完成」。找出确实办完的，本人点一下就能关掉；没办完的不用管。

## 要交出什么

当前文件夹的 `donecheck.json`：只列办完的事。一件都没办完就写 `[]`，这是正常结果。

## 输入

- `items.json`：本人自己要做、还没关的事。每件有编号 `n`、标题、要做什么（`what`）、做到什么算完（`done_when`）、原话、来源、什么时候进来的（`since`），以及 `after`：从这件事冒出来到现在，来源聊天里的相关消息（程序已找好）。

## 怎么判断

1. **先看 `after`**：本人或同事说了「已发」「搞定」「已加上」「弄好了」，发了文件或链接，对方回了「收到」「可以了」，并且说的就是这件事，就算办完。
2. **`after` 里没有，再去现场查一下（只读）**：用 `lark-cli` 搜聊天和文档，比如 `lark-cli im +messages-search --query "关键词" --as user`、`lark-cli docs +search --query "关键词" --as user`。要交的是一份文档、一个版本、一条通知的，找找这份东西是不是已经有了。每件事最多查两次，查不到就算没办完。
3. **不算办完**：「我看看」「我处理下」「收到」「好的」只是接下了；只办了一半；说的是另一件相似的事；只是自己推测应该办完了。
4. **拿不准就不写。** 写错一条，本人就不再信这一栏了。

## 输出格式

```json
[{"n": 97, "done": true, "evidence": "[11-25 14:02 李瑞轩] 返回按钮加上了，已经发到测试包", "where": "和李瑞轩的私聊"},
 {"n": 103, "done": true, "evidence": "苹果搜索广告第一期投放计划", "where": "飞书文档", "url": "https://example.feishu.cn/docx/xxx"}]
```

- `evidence`：原样抄那一句，带时间和说话人；在 `after` 里看到的必须一字不差，程序会核对。
- 是在你自己查到的文档或消息里看到的，`url` 写它的链接，`where` 写是哪个群或哪份文档。没有链接、又不在 `after` 里的证据，程序不收。

## 交了之后

心响在这件事旁边写上「看起来已经办完了」和你抄的那句，本人点「完成」才关。本人点「没办完」的，同样这句话以后不会再拿来说。
