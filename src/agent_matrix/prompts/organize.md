# 整理项目和版本：把本人的事归到「项目 → 版本」里

本人要你把他手上的事按项目和版本理清楚：每个版本里有哪些事、谁先谁后、这个版本和下个版本预计还会遇到什么。之后 AI 做每件事都会带上它所在版本的背景，所以要准。

## 要交出什么

当前文件夹的 `organize.json`。

## 输入

- `items.json`：本人最近的事（编号 n、标题、状态、执行方、所在项目、已串起来的前后关系）。
- `projects.json`：已有的项目和版本。
- `profile.md`：关于本人（岗位、产品、在推进的事）。

## 先找他的项目管理表格（只读）

1. 飞书：`lark-cli docs +search --query "版本" --page-size 20 --as user --format json`，也试试「迭代」「需求池」「排期」「里程碑」「Roadmap」。找到多维表格或电子表格后，用 `lark-cli base --help` / `lark-cli sheets --help` 看怎么读，读出版本、需求、状态、负责人、计划时间这些列。
2. 本机：项目文件夹里的 CHANGELOG、版本说明、roadmap 文档也算。
3. 找不到也没关系，就从 `items.json` 的标题和关系里归纳。

## 输出格式

```json
{"versions": [{"project": "示例 App", "name": "2.3", "status": "当前", "period": "11 月", "note": "会员体系改版", "source": "飞书多维表格《需求池》"}],
 "items": [{"n": 12, "project": "示例 App", "version": "2.3"}],
 "links": [{"earlier": 12, "later": 15, "why": "先定规则再做页面"}],
 "expected": [{"project": "示例 App", "version": "2.4", "title": "会员续费提醒", "why": "2.3 上线后表格里排在下一版"}]}
```

- `status` 只用：当前 / 下一版 / 规划中 / 已完成；每个项目最多一个「当前」。
- `items` 只放有把握的；看不出属于哪个版本的不要硬塞。
- `links`：明显有先后的两件事（同一件事的前置、做完这件才能做那件），两边都必须是 `items.json` 里的编号。
- `expected`：表格里排好了还没变成事项的、或者这个版本必然会遇到的事（上线前验收、对外通知），一句话写清为什么。
