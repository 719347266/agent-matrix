# 提取聊天待办：冲着本人、要本人做或跟进的，都收

## 要交出什么

当前文件夹的 `review.json`，结构见 `review.schema.json`：`{"batch_id": …, "actions": […], "skipped": […]}`。`batch_id` 用开头给的值。

**每条候选只有两个去处**：提取成待办（`actions`），或者不收（`skipped`，写明属于哪一类）。私聊的每一条都必须有结论，漏掉会被打回来。

## 输入

- 候选消息文件（开头给了文件名）：本人账号能看到的聊天，代码几乎都交给你了，只去掉了纯客套和表情。每条的 `kind` 只是代码已经知道的事实：

  | kind | 是什么 |
  |---|---|
  | 我说的 | 本人自己说的话 |
  | @你 | 群里 @ 了本人 |
  | 找你的 | 私聊里对方说的话，或者群里提到了本人的名字 |
  | 回你的 | 回复本人发的帖子或话题 |
  | 全员 | @here / @channel / @所有人 的通知 |
  | 群聊 | 群里其他的话：没点名任何人，或者点的是别人 |

- 每条还带 `context`（之前的两句）和 `after`（之后同一个群里说的话）。
- `related_items.json`：本人手上的事和最近两周做完的事，用来认出「接着哪件事做」。

冲着谁、有没有要本人做的事，**全部由你判断**。代码不看名字、不看求助字眼，因为大量真正的活都不点名：客户在群里问一句「这个积分怎么没到账」，同事接着本人的话说「那你们帮忙升级一下」。

## 第一步：这句话冲着谁

先看归属，不看话题。

- **冲着本人**：
  - 私聊里对方说的；@本人的；全员通知（本人也在里面）。
  - **在接本人说过的话**：看 `context`，本人刚说完，对方紧接着回答、追问、提要求（本人发了方案，对方回「那我先装上，你们帮忙升级一下」）。
  - **群里没点任何人的求助、提问、报问题**：谁看见谁接，本人也是接的人。客户群里尤其如此，客户问问题、报问题、要东西几乎从不点名，都是在找我们这边处理（「海外站点要开会员积分，是直接装 app 吗」「会员页积分显示不对」）。
  - 在推进本人手上某件事的。
- **不冲着本人**：@ 的是别人、明确在问某个人（「@小李 规则看你这边」）；同事之间互相交办，或在讨论他们自己的活，本人只是旁观；闲聊、寒暄、纯表态、和本人无关的通知。哪怕话题和本人手上的事一样，也不算。

**本人自己说的话**（「我说的」）：本人答应要做的（「我来」「明天给你」「发个店铺来，我帮你升级」）就收，执行方按事情本身判断；本人只是回答、附和、已经做完（「都升级好了」）的不收。本人说「已经做完了」，也是在告诉你前面对方提的那件事办完了。

**同一个人连着发的几条合起来读**（看 `context` 和 `after`）。人常把一句话拆开发：先发截图，再描述问题，最后丢个链接。合起来是一件事的，只在描述最完整的那条上提取一次，其他几条写进 `skipped`，类别填「并入另一条」。

## 第二步：收不收

冲着本人、而且有一件要本人做或跟进的事，就收。**不需要「帮忙」「麻烦」这类字眼**：

- 交办、请求，哪怕是问句：「有没有空升级一下包」「能帮我加个权限吗」「借我登一下」。
- 报问题、描述现象：「网页比例 100% 时，这个会员弹窗只露出一点」「导出的数据不对」。报给本人的问题，就是要本人处理。
- 发来链接、截图、工单、PR，请本人看。
- 本人自己说要做的。
- 客户或同事在群里提的问题、要求，没点名任何人，也没人接走（`after` 里没有别人说「我来看」）。

**先看 `after`**：后面已经办完了（本人回了「已发」「搞定」、发了文件），或者对方说「不用了」、事情已经说定，就不收，类别填「已办完」。本人只回了「我看下」「收到」不算办完。

**不收必须说出类别**，只能是下面之一（原样照写）：

| 类别 | 什么时候用 |
|---|---|
| 闲聊 | 寒暄、玩笑、吐槽、和工作无关 |
| 表态 | 「好的」「收到」「👍」，只是回应，没有新的事 |
| 无关通知 | 和本人没关系的通知、播报 |
| 已办完 | 见上面「先看 `after`」 |
| 点了别人 | 话是说给别人听的、要别人去做 |
| 同事的活 | 同事之间在讨论他们自己的事 |
| 并入另一条 | 和本批里另一条已提取的待办是同一件事 |

**说不出属于哪一类，就收。** 私聊尤其如此：对方专门找本人说话，拿不准的就提取，让本人自己决定做不做。

## actions 的字段

- `message_id`：候选里的原值。`quote`：那条消息里一段原样的文字。
- `title`：写成本人要做的事（「看会员弹窗在 100% 缩放下只露一点的问题」），不要照抄原话。
- `commitment_phrase`：消息里最能说明这件事的原话：请求的那句、报问题的那句、本人答应的那句。
- `owner_name`：冲着本人的事（第一步判过的，包括群里没点名的求助、客户的问题），填本人全名。别人的事只有两种情况能填：发消息的人自己承诺，填发消息的人；消息里点了名（「小王你……」），填被点名的人的全名。其他情况填 null。
- `due_date`、`due_phrase`：消息里明确写了哪一天才填，按发消息那天换算。「下周」「月底」「过两天」这类说不出确切日期的，都填 null。
- `executor`：本人的事里，AI 能独立做完的（起草、整理、调研、做表）填 "AI"；要本人拍板、发出去、审批的填 "我"；别人的事填 "别人"。
- `confidence`：群里的待办低于 0.8 不会入表；私聊的不看这个分数，照实填。
- `accepted_quote`：别人请本人做的事，`after` 里本人回了愿意接的话（「好的」「我来」「没问题」「行」），把本人那句原样照抄进来；本人没回、只回了问题、或者拒绝的，留 null。程序会在 `after` 里核对。本人自己说要做的事不用填。
- `follows`：明显是 `related_items.json` 里某件事的下一步（做完那件才有这件、要用那件的成果），填它的编号。只是话题相近不填；是同一件事就不该新建；拿不准不填，填错会被忽略。

和本人还没完成的某件事是同一件事的，照常提取，代码会自动并进那件事。

## 交了之后

校验和入表由程序做。没通过时程序会把原因发回来：只改有依据的字段。因为原话不在消息里、负责人对不上而没通过的：群里的直接删掉那条；私聊的改好字段，或者挪进 `skipped` 写明类别。
