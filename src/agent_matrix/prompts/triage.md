# 判断新进来的事：要不要做、谁来做

## 要交出什么

当前文件夹的 `triage.json`：`items.json` 里每件事一条判断。

## 输入

- `items.json`：刚进表、还没定谁来做的事。每件有标题、要做什么、原话、来源、`version`（所在项目和版本，空 = 还没归版本），以及 `after`：从这件事冒出来到现在的相关聊天（程序已找好）。
- `open.json`：本人手上还没做完的事（编号 n、标题、状态、所在版本），用来找前后关系。
- `versions.json`：本人现有、没完成的项目和版本，用来给没归版本的新事找归属。

**先看 `after` 再下判断。** 很多事本人已经在对话里办完了，或者对方说不用了，只是现在才被捞起来。`after` 不够，可以用 `lark-cli` 只读地再查（搜聊天、读文档）。

## 五种判断

| decision | 什么时候 | 必须写 |
|---|---|---|
| `done` 已经办完 | `after` 里能看到本人已经做了：发了文件、回了「已发」「搞定」、对方确认收到 | `evidence` 写出是哪一句；有交付链接写进 `url` |
| `skip` 不用做 | 随口一说、对方说不用了、和别的事重复、已经过时 | `reason` 写清原因 |
| `ai` AI 独立做 | 结果是一份文档或表格：起草、整理、调研、汇总、做表、写方案、准备材料 | |
| `prep` 本人做、AI 先备材料 | 要本人拍板、对外沟通、开会、审批，但 AI 能先备材料 | |
| `me` 只能本人做 | AI 备材料也帮不上忙 | |

- 没把握就不要判 `done` 或 `skip`；拿不准该谁做时判 `prep`。
- 对外发送、提交审批、付款、删除、发布：不能判 `ai`，最多 `prep`。
- `reason`：30 字以内，写给本人看。

## 顺带补上前后关系（只给 ai / prep / me 的事补，看得出来才写）

- `before`：开始前要先做完的事，填 `open.json` 里的编号。
- `after`：做完后接着要做的事，填编号。（这是输出字段，和输入里的聊天 `after` 不是一回事。）
- `version`：新事的 `version` 为空、又明显属于 `versions.json` 里某个版本时，写 `{"project": "项目名", "version": "版本名"}`，名字原样照抄。
- `expected`：新事所在版本预计还会遇到、表里还没有的事（上线前验收、配套的文档或通知）。每条写 `title`、`why`，知道日子就写 `due`（如 `2026-11-28`）。`version` 为空的事不写。
- 每项最多 3 个；不写新事自己的编号；三项都可以省略。

## 输出格式

```json
[{"n": 47, "decision": "done", "reason": "本人已在群里发了审核材料", "evidence": "[11-17 15:02 本人] 材料已提交，电话也认证了"},
 {"n": 49, "decision": "ai", "reason": "按现有岗位要求起草 JD，AI 能独立完成", "before": [31], "after": [52],
  "version": {"project": "招聘", "version": "12 月"},
  "expected": [{"title": "JD 发布前请用人部门确认", "why": "岗位要求还没定稿", "due": "2026-11-28"}]},
 {"n": 50, "decision": "skip", "reason": "对方说这周先不招了"}]
```
